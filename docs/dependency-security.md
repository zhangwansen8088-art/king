# 依赖更新与漏洞处理

## 自动检查

持续集成会在安装锁定依赖后执行：

```bash
pnpm security:audit
```

该命令只检查生产依赖，并固定使用 npm 官方审计接口。发现高危或严重漏洞时构建失败。Dependabot 每周一检查 npm 依赖和 GitHub Actions，自动创建小版本、补丁及单独的大版本升级请求。

持续集成还会执行 `pnpm peers check`，阻止不兼容的同侪依赖（Peer Dependency）进入主分支。

## 人工处理

1. 先查看漏洞路径、影响范围和修复版本，不只根据版本号猜测风险。
2. 同大版本补丁优先直接升级；传递依赖无法由上游及时升级时，才在根 `pnpm-workspace.yaml` 的 `overrides` 中做最小覆盖。
3. 大版本升级必须单独提交，并执行 `pnpm install`、`pnpm db:generate`、`pnpm check` 和适用的隔离 PostgreSQL 集成测试。
4. 审计通过只代表已知漏洞数据库没有报告，不代表完成渗透测试；认证和权限改动仍需独立安全验收。

## 当前覆盖

- `multer` 统一为 `2.5.0`，修复待处理上传过滤器在请求结束时引发的拒绝服务漏洞。
- `deepmerge-ts` 统一为 `8.0.0`，修复递归对象图导致的栈耗尽漏洞。
- `js-yaml` 统一为 `5.4.1`，修复合并键数量限制不足导致的 CPU 消耗漏洞。
- Prisma Client 和 Prisma CLI 同步使用 `6.19.3`，避免客户端与命令行版本不一致。
- `webpack` 统一为 `5.112.2`，满足 `schema-utils` 的最低兼容要求；该项仅用于开发构建，不属于生产依赖。

这些覆盖项在上游更新并解除旧版本限制后应重新评估，确认不再需要时可以删除。
