# 安全设计

## 登录

- 密码使用 Argon2id 哈希，数据库不保存明文密码。
- 访问令牌为短期 JWT，前端只保存在内存，不写 `localStorage`。
- 刷新令牌是随机不透明字符串，只放 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 数据库只保存刷新令牌 SHA-256 哈希；刷新时轮换令牌。
- 注销只撤销当前会话；账号级“全部下线”（撤销该账号全部刷新会话）**尚未实现**，不能当作现有能力对外承诺。
- 登录失败按账号和客户端 IP 两个范围分别计数，原始账号和 IP 不写入计数表；两个范围都保存 SHA-256 哈希。
- 默认在 15 分钟窗口内连续失败 5 次后锁定 15 分钟。达到阈值或仍在锁定期时返回 HTTP `429` 和 `retryAfterSeconds`，前端不得继续自动重试。
- 登录成功只清除对应账号的失败计数。IP 计数按窗口自然过期，避免攻击者切换合法账号重置来源限制。
- 不存在的账号也会执行一次 Argon2id 校验，降低通过响应耗时枚举账号的风险。
- 登录失败、账号成功登录和首次锁定均写入审计；锁定审计和锁定告警只包含哈希、计数范围和锁定时间，不包含账号、密码或原始 IP。
- 可信代理只接受明确 IP、CIDR 或 Express 预定义网段。来源未命中可信代理时忽略 `X-Forwarded-For`，直接使用 TCP 地址。
- 登录成功会写入审计日志；登录锁定告警复用通用 Webhook，发送失败不会改变登录接口响应。
- 生产依赖通过 npm 官方漏洞数据库检查，高危和严重漏洞会使持续集成失败。

## 跨站请求伪造防护

- Cookie 接口校验请求 `Origin` 是否在允许名单。
- 刷新和注销同时要求 `X-CSRF-Token`，服务端与当前刷新会话中的哈希比对。
- 不使用宽松跨域；生产环境只允许正式前端域名。

## 权限

- API 按 `PROMOTER` 和 `ADMIN` 角色校验。
- 商户账号不提供前端入口；只有管理员可执行商户管理、任务发布和审核。
- 推广客户只能读取自己的提交、钱包、提现和流水。
- 管理员受控调账必须填写原因，并产生资金流水与审计记录。

## 日志与告警

- 请求日志只记录方法、无查询参数的路径、状态码、耗时和请求 ID。
- 5xx Webhook 告警只发送错误类型等最小诊断字段，不发送原始错误消息和业务数据。
- 生产 Webhook 应使用 HTTPS；内网 HTTP 必须限制在可信网络且禁止公网访问。
- Webhook 发送超时、失败和重复冷却是隔离处理的，不会改变接口响应。
- 审计日志清理默认关闭；启用后至少保留 30 天并采用分批删除，禁止低于保留期误删。
- 审计清理本身写入系统审计记录，但生产启用仍需单独审批和备份。
- 登录失败计数每小时清理一次，默认只删除超过 24 小时且锁定已失效的记录；活动锁定不会被清理任务删除。

## 后续上线前必须完成

- 管理员多因素认证（MFA）。
- 在预发布环境验证 Coolify 或其他外层代理到 Nginx 的真实 IP 传递链路，确认锁定不会把多个用户误判为同一代理 IP。
- 异地登录告警和会话管理页面。
- 密钥托管、定期轮换与泄露应急流程。
- 依赖漏洞扫描、代码扫描和渗透测试。
