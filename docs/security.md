# 安全设计

## 登录

- 密码使用 Argon2id 哈希，数据库不保存明文密码。
- 访问令牌为短期 JWT，前端只保存在内存，不写 `localStorage`。
- 刷新令牌是随机不透明字符串，只放 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 数据库只保存刷新令牌 SHA-256 哈希；刷新时轮换令牌。
- 注销只撤销当前会话；“全部下线”撤销该账号全部刷新会话。
- 登录成功会写入审计日志；当前尚未实现登录限速和失败告警。
- 生产依赖通过 npm 官方漏洞数据库检查，高危和严重漏洞会使持续集成失败。

## 跨站请求伪造防护

- Cookie 接口校验请求 `Origin` 是否在允许名单。
- 刷新和注销同时要求 `X-CSRF-Token`，服务端与当前刷新会话中的哈希比对。
- 不使用宽松跨域；生产环境只允许正式前端域名。

## 权限

- API 按 `PROMOTER` 和 `ADMIN` 角色校验。
- 商户账号不提供前端入口；只有管理员可执行商户管理、任务发布和审核。
- 推广客户只能读取自己的提交、钱包、提现和流水。
- 管理员受控调账必须填写原因，并产生资金流水与审计记录。

## 日志与告警

- 请求日志只记录方法、无查询参数的路径、状态码、耗时和请求 ID。
- 5xx Webhook 告警只发送错误类型等最小诊断字段，不发送原始错误消息和业务数据。
- 生产 Webhook 应使用 HTTPS；内网 HTTP 必须限制在可信网络且禁止公网访问。
- Webhook 发送超时、失败和重复冷却是隔离处理的，不会改变接口响应。
- 审计日志清理默认关闭；启用后至少保留 30 天并采用分批删除，禁止低于保留期误删。
- 审计清理本身写入系统审计记录，但生产启用仍需单独审批和备份。

## 后续上线前必须完成

- 管理员多因素认证（MFA）。
- 登录接口限速、失败次数锁定和告警。
- 受信任代理与真实客户端 IP 配置。
- 登录失败告警、异地登录告警和会话管理页面。
- 密钥托管、定期轮换与泄露应急流程。
- 依赖漏洞扫描、代码扫描和渗透测试。
