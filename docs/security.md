# 安全设计

## 登录

- 密码使用 Argon2id 哈希，数据库不保存明文密码。
- 访问令牌为短期 JWT，前端只保存在内存，不写 `localStorage`。
- 刷新令牌是随机不透明字符串，只放 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 数据库只保存刷新令牌 SHA-256 哈希；刷新时轮换令牌。
- 注销只撤销当前会话；“全部下线”撤销该账号全部刷新会话。
- 登录接口限速，并记录成功、失败和撤销审计。

## 跨站请求伪造防护

- Cookie 接口校验请求 `Origin` 是否在允许名单。
- 刷新和注销同时要求 `X-CSRF-Token`，服务端与当前刷新会话中的哈希比对。
- 不使用宽松跨域；生产环境只允许正式前端域名。

## 权限

- API 按 `PROMOTER` 和 `ADMIN` 角色校验。
- 商户账号不提供前端入口；只有管理员可执行商户管理、任务发布和审核。
- 推广客户只能读取自己的提交、钱包、提现和流水。
- 管理员受控调账必须填写原因，并产生资金流水与审计记录。

## 后续上线前必须完成

- 管理员多因素认证（MFA）。
- 受信任代理与真实客户端 IP 配置。
- 登录失败告警、异地登录告警和会话管理页面。
- 密钥托管、定期轮换与泄露应急流程。
- 依赖漏洞扫描、代码扫描和渗透测试。
