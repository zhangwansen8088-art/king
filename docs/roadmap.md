# 实施路线图

## 已完成

- 技术栈已落地：React、Vite、TypeScript、Tailwind、NestJS、PostgreSQL、Prisma、Docker Compose。
- 管理员与推广客户可以登录；商户没有独立登录入口，商户资料统一写入管理员后台。
- 商户资料、调账、任务发布、凭证审核、提现和审计日志已形成后台闭环。
- 金额使用整数分，资金动作写入不可修改的流水，并通过数据库唯一键防止重复入账。
- 格式、类型、单元测试、生产构建和 Compose 配置已通过本地检查。
- 新项目已建立独立 Git 仓库和首个工程基线提交；尚未连接和推送 GitHub。

## 正在进行

### 第一阶段：工程封版

- 增加 GitHub Actions 持续集成（CI），每次提交自动检查格式、类型、测试和生产构建。
- 在独立 PostgreSQL 测试库验证迁移、种子、发布、领取、审核、返佣、退款和提现。
- 保持 `main` 可构建、可回滚；功能改动使用 `codex/` 前缀分支。

### 第二阶段：隔离环境验收

- 已完成旧 SQLite 只读审计和表映射盘点；真实迁移仍等待业务对方书面确认数据源、资金归属及二三级返佣规则。
- 已在全新 PostgreSQL 17 容器执行 `prisma migrate deploy`，未连接正式数据库。
- 已完成种子和 17 项业务闭环验收，覆盖重复发布、重复审核、余额不足、并发领取和并发打款。
- 已完成同一 PostgreSQL 实例内的备份、恢复和逐表内容核对；还需在独立服务器实例、加密备份和异地副本条件下复验。
- 完整证据、数据库版本、校验值和复验命令见 [第二阶段隔离验收记录](stage-2-acceptance.md)。

### 第三阶段：长期维护能力

- 审计日志已改为服务端分页，并支持按动作、实体类型筛选。
- 任务列表已改为服务端分页，并支持按任务状态筛选和调整每页数量。
- 凭证审核列表已改为服务端分页，并支持按审核状态筛选和调整每页数量。
- 提现列表已改为服务端分页，并支持按处理状态筛选和调整每页数量。
- 资金账户列表已改为服务端分页，并支持按角色、账号状态筛选和调整每页数量。
- 商户资料列表已改为服务端分页，并支持按账号状态、关键词筛选和调整每页数量。
- 商户资料已支持按当前筛选条件导出 CSV，包含中文表头、UTF-8 BOM 和公式注入防护。
- 任务发布已改为商户关键词远程搜索，避免商户数量增长后一次性加载完整下拉列表。
- 已增加请求关联 ID、结构化访问日志、存活探针和数据库就绪探针；默认不记录请求体、Cookie、令牌和查询参数。
- 已增加服务端 5xx 告警：通用 Webhook 默认关闭，失败不影响业务响应，并对相同错误冷却去重。
- 已增加审计日志保留策略：默认关闭，启用后至少保留 30 天，按批清理并写入系统审计记录。
- 运维能力测试结果、剩余限制和回滚方式见 [第三阶段运维能力验收记录](stage-3-acceptance.md)。
- 已提供每日 PostgreSQL 全量备份脚本、SHA-256 校验和 14 天默认保留策略。
- 待配置 WAL（预写日志）归档、加密、异地副本、独立实例恢复演练和发布记录。
- 待建立依赖更新、漏洞扫描和版本发布流程。

### 第四阶段：安全加固

- 登录限速、管理员多因素认证（MFA）、可信代理和真实客户端 IP 配置属于认证与权限高风险改动，实施前先写备份、回滚和验收方案。
- 增加会话管理页面、异常登录告警和敏感操作二次确认。
- 上线前完成渗透测试和依赖漏洞修复。

### 第五阶段：生产部署

- 准备 VPS、正式域名、HTTPS、Coolify、数据库持久盘和异地备份。
- 生产部署属于高风险操作，必须单独审批，不能与普通代码提交一起执行。
- 先预发布验收，再灰度切换；新系统和旧系统不能同时写入同一笔资金。

## 上线门槛

1. GitHub 持续集成全部通过。
2. 隔离 PostgreSQL 迁移、种子、完整闭环和异常流程通过。
3. 备份恢复演练通过，恢复后的数据与金额对账一致。
4. 正式密钥、域名、HTTPS、告警、值班联系人和回滚负责人都已确认。
5. 真实资金、旧数据迁移和生产发布分别审批，禁止顺手执行。
