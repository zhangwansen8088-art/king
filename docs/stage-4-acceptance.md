## 已验证配置

- 默认阈值：15 分钟窗口内失败 5 次，锁定 15 分钟。
- 锁定响应包含准确的正整数 `retryAfterSeconds`，前端禁止自动重试。
- Nginx 使用 `$remote_addr` 覆盖客户端传入的 `X-Forwarded-For`。
- API 只信任 `TRUST_PROXY_CIDRS` 中明确配置的 IP、CIDR 或预定义网段。
- PostgreSQL 使用单条原子 UPSERT 累计失败次数，并发请求不会覆盖计数。

## 风险与回滚

- 新表 `LoginAttempt` 只存安全计数，不回写账号或 IP 明文；生产迁移前仍须备份数据库并确认迁移窗口。
- 若登录锁定造成误伤，可先将 `LOGIN_MAX_FAILURES` 调到允许范围内较高值并重新部署；不要直接删除活动锁定记录。
- 代码回滚使用 `git revert <本轮提交哈希>`，再验证迁移兼容性和登录接口。数据库迁移回滚必须先备份，并按 `apps/api/prisma/migrations/20261025060000_add_login_attempt/migration.sql` 的逆向步骤在隔离库演练。
- 生产部署、数据库迁移、MFA 和认证权限变更必须分别审批，不能与本轮代码提交混为一次发布。
