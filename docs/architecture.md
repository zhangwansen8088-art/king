# 架构说明

## 架构选择

系统采用模块化单体（Modular Monolith），不拆微服务。任务、审核、钱包、提现、审计共享一套严格事务，拆成多个服务会先增加一致性和运维成本。

```text
浏览器
  ├── 推广客户工作台
  └── 管理员后台（含商户、任务、审核、资金）
          │ HTTPS
          ▼
       Nginx / Coolify
          │
          ▼
       NestJS API
          │
          ├── JWT 认证
          ├── 业务事务
          ├── Swagger 文档
          └── Prisma
                 │
                 ▼
            PostgreSQL
```

## 目录职责

- `apps/api`：NestJS API、Prisma 模型、认证、业务事务和自动测试。
- `apps/web`：React 单页应用，只保留推广客户端与管理员后台。
- `packages/contracts`：前后端共用的状态、角色、接口类型和金额格式化。
- `apps/api/prisma/migrations`：PostgreSQL 版本化建表和升级脚本。
- `docs`：部署、安全、备份、回滚和旧系统基线。
- `compose.yml`：Nginx、API、PostgreSQL 和迁移任务编排。

## 关键不变量

1. 所有金额以整数“分”存储，接口传输字符串形式的整数分。
2. 同一事务内完成单据状态、钱包余额和资金流水变化。
3. 每条资金流水有数据库唯一幂等键，重复请求不能重复入账。
4. 管理员只能通过受控调账接口改余额，不能直接覆盖余额。
5. 审核、任务结束、提现处理使用行锁和串行化事务。
6. 资金流水只追加，不修改、不删除。
7. 商户没有独立前端；管理员后台代替商户执行任务发布和凭证审核。

## 已知边界

- 当前未接入真实支付、真实广告平台自动曝光采集、身份认证或税务系统；曝光数据仅支持管理员人工导入，落在 `ExposureDaily` 表，并由管理员查询接口与推广客户只读查询接口提供。
- 当前没有迁移旧 SQLite 数据。
- Coolify 只是部署控制台，不提供备份和高可用保障。
